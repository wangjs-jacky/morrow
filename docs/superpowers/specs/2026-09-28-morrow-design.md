# Obsidian 外观预设：第一版方案

日期：2026-09-28　｜　状态：V1 已实现　｜　[交互原型](../../../design/prototype.html)

## 目标与范围

让不懂 CSS 的 Obsidian 用户通过**一张包含侧栏、正文、属性和 Mermaid 的预览**选择外观，调整少量开关后点击「应用」，立即得到与预览相符的效果；可以恢复上一次设置。第一版面向桌面版，先交付一个经过真实 Obsidian 验证的「深色阅读」预设。原型中的 Minimal 浅色只保留为后续方向，不计入第一版承诺。

## 用户流程

用户首次安装主题和配套插件，在 Obsidian 内打开插件界面。界面以一张可交互的 Obsidian 窗口为主：选择预设、展开「自定义细节」、调整行号、笔记属性、Mermaid、正文宽度和主题色；每次调整先更新预览。点击「应用」才保存为当前配置，并显示结果与「撤销」入口。「恢复默认」只重置当前预设的调整草稿，不改动笔记内容。安装是首次准备工作；**一键切换指安装完成后的预设应用**。

## 实现分工与取舍

| 方案 | 判断 |
| --- | --- |
| 只发布主题 | 安装简单，但无法提供这张可交互预览和完整的应用／撤销流程。 |
| **主题 + 配套插件** | **第一版采用。** `theme.css` 负责外观；插件负责预览界面、预设状态、应用和撤销。 |
| 独立桌面换肤器 | 可控制更多本地配置，但安装和跨平台维护成本高；第一版没有必要。 |

主题通过 Obsidian 的 CSS 变量和自身选择器定义侧栏、正文、属性区、Mermaid 的样式。插件应用时切换**本主题专用的样式类**，将版本化的预设 ID 和选项保存在插件数据中；重启后恢复，禁用插件时移除它添加的类。插件不修改 Markdown、YAML 原文或其他主题的文件，也不依赖未公开的换主题接口。若主题未启用，插件明确提示用户先在 Obsidian「外观」中启用，不显示虚假的应用成功。

## 行号与属性的真实边界

「显示行号」和「文档中的属性」本身是 Obsidian 编辑器设置。第一版首次使用时提示用户将官方设置设为**基础配色＝深色、显示行号＝开启、文档中的属性＝可见**；之后主题开关可以在这两个编辑器设置基础上控制其视觉显隐。若基础设置不满足，界面须标出原因并指向对应的官方设置，不能声称 CSS 能生成真正的行号或把已隐藏的属性恢复出来。属性开关只控制显示，不删除 YAML；「源码 YAML」模式仍由 Obsidian 官方设置切换。正式预览应展示 **Live Preview 编辑视图**，因为现有 HTML 原型将“阅读视图”与行号放在一起，需要修正。

## 第一版验收

1. 在独立测试仓库安装主题与插件后，预览的正文、侧栏、属性、Mermaid 与真实 Obsidian 的参考截图逐项核对；所有预览内容使用公开的示例笔记。
2. 调整选项仅影响草稿；「应用」立即生效，重启后保持；「撤销」还原应用前状态，主题未启用时不会误报成功。
3. 行号与属性在官方前置设置满足时可见、可隐藏、可恢复；切换过程不改动任何笔记内容。
4. 第一版先在 macOS 桌面版验证；移动端、浅色预设、在线主题库和网页一键唤起 Obsidian 留待后续版本。

最终采用独立编写的 Morrow 主题 CSS，没有复制 Cupertino 源码。主题和插件按仓库中的 MIT 许可证发布。
