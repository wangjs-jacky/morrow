# Reading Studio V2：可继承的深色风格包

日期：2026-09-28　｜　状态：已实现并发布 [v0.2.0](https://github.com/wangjs-jacky/obsidian-reading-studio/releases/tag/v0.2.0)

## 用户目标

在现有「一张预览 → 调整细节 → 应用」流程里，提供足够多、视觉上确实不同的主题选择。首次安装后不用理解 CSS，也不必换一套 Obsidian 主题文件；切换预设后先看草稿效果，点应用才改变真实仓库，并可撤销。已安装 V1 的配置继续有效。

## 首批风格

V2 在同一个 Reading Studio 主题里交付五款**深色**风格包：保留「深色阅读」，新增「Cupertino 夜色」（圆角与柔和侧栏）、「极简石墨」（中性色、扁平布局）、「柔雾夜读」（柔和粉彩）和「棱镜聚焦」（更鲜明的高对比重点）。每款独立定义应用背景、侧栏、正文、属性区和 Mermaid 色板与局部排版，不能只改变强调色。所有预览继续使用项目自己的虚构笔记。

Cupertino、Minimal、Catppuccin 和 Prism 的视觉语言是调研参考；不复制它们的 CSS 或宣传图。关联上游和许可证列在 `docs/theme-inspiration.md`。可复用的不是一整份外部 `theme.css`，而是 Reading Studio 的共享组件样式 + 各风格包覆盖的 CSS 变量。新风格可以沿用共享结构，增添少量专属选择器。

## 交互与数据

预设选择只重建当前草稿并更新预览；行号、笔记属性、Mermaid、正文宽度和强调色仍是当前预设草稿上的独立覆盖项。「恢复默认」恢复**当前预设**的默认选项。「应用」保存完整的预设 ID 与覆盖项，重启后复原；「撤销」恢复前一个预设及其选项。V1 的 `version:1` 存储结构不变，因为字段结构未变，只扩充合法预设 ID。未知预设 ID 安全回退。已应用 V1 深色阅读的用户不需要迁移操作。

每款预设都有自己的应用类名 `reading-studio-preset-*`。插件仅管理这些命名空间内的 body 类，不修改笔记、YAML、Obsidian 核心设置或其他主题。主题 CSS 的基础变量与共享组件规则保持一份；预设规则只覆盖变量与少量确实独特的局部样式。预览 CSS 用同一套命名的视觉令牌表达这些差异，并通过截图与真实 Obsidian 核对。

## 深浅色边界

首批只交付深色包，以保持「点应用就生效」。Obsidian 的公开插件 API 可以读取当前深浅色状态，但没有公开的切换基础配色方法；插件继续要求用户先选择 Obsidian 深色基础配色。原先不可用的 Minimal 浅色占位不作为已实现预设。未来浅色包须另行设计明确的模式切换流程，不调用未公开 API，也不悄悄改写 `app.json`。

## 验收

1. 五个预设可以选择、预览、应用、刷新后保持，跨预设撤销恢复完整旧配置；V1 已保存数据仍正常。
2. 每个预设的侧栏、正文、属性和 Mermaid 至少有一组可见的独立差异，同时共用行号/YAML/宽度等开关。
3. 未满足主题、深色模式或编辑器前置设置时不会显示应用成功。
4. 自动测试、Ego 浏览器 E2E 和隔离 Obsidian 仓库的真实渲染检查通过；原有仓库配置不用于测试。
